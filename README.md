# 发版闸（Shipgate）

骨架：发版申请入闸 → 环境晋升裁决 → 放行/回滚窗 → 发布结果对账

- 前端 http://127.0.0.1:6800
- API http://127.0.0.1:11800
- 数据库环境变量 `SHIPGATE_DB`（容器内默认 `/data/shipgate.db`）

```bash
docker compose up -d --build
```

## 关闸与晋升事务袋的争用（整站一种，已敲定）

环境链跃迁走**两阶段晋升事务袋**（`promote_txns`，状态机 `进行中 → 已落成 / 已切断`）：

1. **进袋**：`POST /api/发版单/{id}/晋升` 内部阶段一，校验（含既有「维护窗硬拒」入场策略）后登记事务袋并提交，袋行即对关闸可见。
2. **落成**：阶段二与关闸写口在库级串行（`BEGIN IMMEDIATE`），谁先提交谁生效。

敲定的争用臂为**关闸优先**，不设开关、不弹选项：

- 关闸提交成功即切断该环境全部在途事务袋；被切断的跃迁**整笔失败、回到争用前**——不改应用环境列、不改发版单当前环境、不写放行事件、不动实例，态势格不计闸外成功，发版单不记已放行。
- 跃迁先落成则是普通闸内跃迁，关闸随后正常落下、切断数为零。
- 可核事实整站一种形态：事务袋行（`entered_at` 进袋戳、`decided_at` 落决戳、`cut_by_window_id` 切断窗）+ `release_windows.closed_at` 关闸提交戳 + 审计时序（`晋升袋` 进袋/落成/闸关切断、`放行窗` 窗关），同源同时、可重放。
- 对账 `/api/对账` 给出**事务袋分桶**（进行中/已落成/已切断）与**闸外跃迁**桶——关闸优先臂下恒为空，非空即违例（切断袋留放行事件、或切断袋目标环境已落且无落成袋）。
- 「维护窗硬拒」是既有入场策略（闸已关时新晋升在入场即拒、不进袋），与本争用臂一致，未重做。

### 对照场景复现（夹具入口 `/夹具` 页或 API）

| 场景 | 步骤 |
| --- | --- |
| 关闸抢先 | `POST /api/夹具/争用` `顺序=关闸抢先`，或 进袋→关闸→落成 |
| 跃迁抢先 | `POST /api/夹具/争用` `顺序=跃迁抢先`，或 进袋→落成→关闸 |
| 做到一半 | `POST /api/夹具/进袋` → `POST /api/夹具/关闸` → 查快照 → `POST /api/夹具/落成` |
| 闸外跃迁进对账 | 任一争用后查 `/api/对账` 的 `闸外跃迁`（恒空）与 `事务袋分桶` |
| 并发双写口 | `POST /api/夹具/争用` `顺序=同发`（落成与关闸两线程同发） |
| 对齐快照 | `GET /api/夹具/快照`：闸态、事务袋、发版单、环境列、在途态势、对账分桶、审计尾，单事务同刷 |

其他探针：`GET /api/晋升事务袋?状态=`（在途事件）、`GET /api/审计?类别=&关联编号=`（审计时序过滤）、`POST /api/夹具/关闸`（关闸写口探针，回报切断清单）、`POST /api/发版单/{id}/晋升`（发版单回执，被切断返回 409）。
